# 11. Functional Requirements Specification: SignTalk AI

**Document ID:** STAI-DOC-P1P1-011  
**Project Name:** SignTalk AI  
**Document Status:** Approved Research Specification (Phase 1 — Part 1)  

---

## 1. Functional Requirements Overview

The functional requirements (FRs) define the precise behavioral and operational capabilities of SignTalk AI. Requirements are prioritized using the standard MoSCoW framework:
- **Must Have (M):** Mandatory core capabilities without which the system cannot function or be evaluated.
- **Should Have (S):** Critical supporting capabilities that provide necessary robustness and usability.
- **Could Have (C):** Desirable capabilities to be implemented if time and compute permit.
- **Won't Have (W):** Explicitly deferred capabilities (aligned with Out of Scope).

## 2. Requirements Matrix

| ID | Requirement Statement | Priority | Architectural Subsystem | Rationale | Acceptance Criterion |
| :---: | :--- | :---: | :--- | :--- | :--- |
| **FR-001** | **Camera Stream Ingestion**<br>The system must capture live monocular RGB video frames from a connected user webcam. | **Must Have** | CV Ingestion Frontend | Primary visual input for sign capture. | Ingests frames at $\ge 20$ FPS at 720p resolution without visual stutter or memory buffer leaks. |
| **FR-002** | **Hand Landmark Tracking**<br>The system must extract 21 three-dimensional skeletal coordinates $(x, y, z)$ for each detected hand (left and right) per frame. | **Must Have** | MediaPipe Hands Pipeline | Hand shape and finger articulation form the core manual lexical parameters of ISL. | Extracted array of shape $(2, 21, 3)$ returned per frame with visibility confidence $> 0.5$. |
| **FR-003** | **Upper-Body Pose Tracking**<br>The system must extract key upper-body landmarks (shoulders, elbows, wrists, nose, eyes, ears). | **Must Have** | MediaPipe Pose Pipeline | Defines spatial reference anchors (e.g. signs articulated at chest vs chin) and arm kinematics. | Pose array of 11 upper-body keypoints extracted synchronously with hand landmarks. |
| **FR-004** | **Facial Non-Manual Marker Extraction**<br>The system should extract a filtered subset of 40 facial mesh landmarks covering eyebrows, lips, and jaw contours. | **Should Have** | MediaPipe Face Mesh | Captures non-manual grammatical signals (question marking, negation, syntactic emphasis). | 40 normalized face coordinates extracted without exceeding a $15\text{ ms}$ processing budget per frame. |
| **FR-005** | **Skeletal Coordinate Normalization**<br>The system must normalize extracted landmarks to be invariant to signer distance, body size, and horizontal camera position. | **Must Have** | Preprocessing & Fusion Module | Prevents model failure when signers sit closer or further from the webcam. | Torso origin centered at $(0, 0, 0)$ with coordinates scaled by shoulder-width distance metric. |
| **FR-006** | **Temporal Sliding Window Construction**<br>The system must maintain an active rolling temporal buffer of $T \in [30, 60]$ normalized landmark frames with a stride of $S \in [5, 10]$ frames. | **Must Have** | Temporal Sequence Manager | Dynamic signs span multiple frames; continuous translation requires overlapping temporal windows. | Yields sliding tensors of shape $(C_{in}, T, N)$ at steady temporal intervals without dropping frames. |
| **FR-007** | **Spatial-Temporal Graph Modeling (ST-GCN)**<br>The system must construct an anatomical landmark graph and extract spatial-temporal motion representations via graph convolutions. | **Must Have** | ST-GCN Encoder | Models biological bone connectivity and joint motion over time without flattening coordinate structure. | Generates dense latent sequence representation $\mathbf{H} \in \mathbb{R}^{T' \times d_{model}}$ from graph inputs. |
| **FR-008** | **Sequence-to-Text Translation (Transformer)**<br>The system must decode the spatial-temporal representations into natural-language English sentences. | **Must Have** | Transformer Sequence Decoder | Translates continuous visual signing sequences into syntactically valid written language. | Autoregressively generates token sequence decoded into grammatically coherent English sentences. |
| **FR-009** | **Live Real-Time Caption Rendering**<br>The system must display translated sentences in a high-contrast, large-font live caption window within the Web UI. | **Must Have** | Web Application UI | Hearing and Deaf users require instantaneous visual text feedback during conversation. | Translated text updates on screen within $< 500\text{ ms}$ from end-of-sign execution. |
| **FR-010** | **Prediction Confidence & Uncertainty Indication**<br>The system must compute and visually display a normalized confidence score ($0.0 - 1.0$) for each translated output. | **Should Have** | Inference Engine & UI | Prevents dangerous silent failures by informing users when predictions are uncertain. | Visual confidence bar displayed: Green for $\ge 0.75$, Amber for $0.50 - 0.74$, Red for $< 0.50$. |
| **FR-011** | **Low-Confidence & Unsupported Sign Handling**<br>When model confidence falls below a configured threshold $\theta_{conf} = 0.50$, the system must flag the output as uncertain and prompt repetition. | **Must Have** | Inference Safety Pipeline | Avoids generating hallucinations or misleading medical/civic interpretations. | Displays explicit banner: *"Low confidence — please repeat sign clearly"* instead of emitting false text. |
| **FR-012** | **Session Lifecycle Controls (Start / Pause / Stop)**<br>The user must be able to start, pause, resume, and terminate a translation session with a single click or keyboard shortcut. | **Must Have** | UI & Session Manager | Provides full user control over camera access, compute consumption, and translation states. | Camera and WebSocket connection cleanly initialize upon 'Start' and release hardware on 'Stop'. |
| **FR-013** | **Interactive Landmark Visualization Toggle**<br>The system should provide a toggle to overlay the detected skeletal landmark graph onto the camera preview. | **Should Have** | Web UI Canvas | Enables signers to verify that their hands and body are properly framed and tracked by the computer vision system. | Clicking "Show Landmarks" renders skeletal lines and joints on the video feed at $\ge 20$ FPS. |
| **FR-014** | **Camera Disconnection & Permission Error Handling**<br>The system must detect denied camera permissions, disconnected webcams, or video freeze and display actionable troubleshooting instructions. | **Must Have** | Error Handling Module | Ensures robust user experience when hardware failures or permission denials occur. | Displays immediate contextual dialog: *"Camera access blocked. Please enable webcam permissions in your browser."* |
| **FR-015** | **Zero Raw-Video Storage Enforcement**<br>The system must process video frames transiently in volatile memory and purge them immediately post-landmark extraction. | **Must Have** | Privacy Protection Subsystem | Guarantees compliance with research ethics, institutional standards, and privacy requirements. | Network monitoring confirms zero outbound video transmission; zero `.mp4` or image files saved to disk. |
| **FR-016** | **Session Translation History Log**<br>The system should maintain a transient local text transcript of all translated sentences generated during the active session. | **Could Have** | Web UI State / History | Enables conversational partners to review preceding sentences or copy the transcript. | Scrollable history panel displayed with a "Copy Transcript" button; cleared upon session close. |
| **FR-017** | **Language / Domain Mode Selection**<br>The system could allow users to select between domain vocabulary modes (e.g., General, Healthcare, Civic Desk). | **Could Have** | Configuration Subsystem | Prunes decoding search space to domain-specific lexicons, enhancing accuracy in specialized settings. | Dropdown menu dynamically loads corresponding language model decoding priors. |
| **FR-018** | **Offline Inference Fallback Verification**<br>The system must execute its core inference pipeline locally without requiring an active external internet connection. | **Must Have** | Backend Architecture | Protects operational viability in low-connectivity or air-gapped institutional environments. | Disconnecting Ethernet/Wi-Fi does not halt translation of supported vocabulary when running local service. |
